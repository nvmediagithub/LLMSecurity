# Архитектура L1 Input Sanitization Layer

## Обзор

L1 слой представляет собой модульную реализацию первичной защиты от prompt-инъекций, построенную на принципах Domain-Driven Design (DDD) и Clean Architecture.

## Domain Layer (Домен)

### Entities (Сущности)

#### L1Attack
Представляет конкретную атаку L1 уровня с ее характеристиками:
- `id`: уникальный идентификатор
- `name`: человеко-читаемое название
- `description`: подробное описание атаки
- `category`: категория атаки (enum L1AttackCategory)
- `payload`: текст атаки
- `expected_result`: ожидаемый результат при успешной атаке
- `metadata`: дополнительные метаданные

#### L1AttackCategory
Перечисление категорий атак:
- `INJECTION`: прямые инъекции
- `NORMALIZATION`: атаки на механизм нормализации
- `SANITIZATION`: обход санитизации
- `LENGTH_ATTACK`: атаки на ограничение длины
- `ENCODING_ATTACK`: атаки через различные кодировки

#### L1LayerConfig
Конфигурация слоя защиты:
- `max_length`: максимальная длина текста
- `enabled_categories`: набор разрешенных категорий атак для тестирования
- `sanitize_zero_width`: флаг включения удаления zero-width символов
- `normalize_unicode`: флаг включения нормализации Unicode

#### L1AttackResult
Результат эмуляции атаки:
- `attack`: ссылка на атаку
- `success`: флаг успешности атаки
- `original_text`: оригинальный текст
- `processed_text`: обработанный текст
- `reason`: причина результата
- `metadata`: дополнительные данные

### Interfaces (Интерфейсы)

#### Репозитории
- `IL1AttackRepository`: управление коллекцией атак
- `IL1ConfigRepository`: управление конфигурацией слоя

#### Эмуляторы и оценщики
- `IL1AttackEmulator`: эмуляция атак
- `IL1ResultEvaluator`: оценка результатов

### Policies (Политики)

#### L1Policy
Содержит бизнес-правила валидации:
- `is_attack_allowed()`: проверка разрешения категории атаки
- `validate_config()`: валидация конфигурации
- `get_default_config()`: получение конфигурации по умолчанию

## Application Layer (Приложение)

### L1ConfigService
Сервис управления конфигурацией:
- Получение текущей конфигурации
- Обновление с валидацией
- Сброс к значениям по умолчанию

### L1EmulationService
Сервис эмуляции атак:
- Запуск эмуляции всех атак на тексте
- Эмуляция конкретной атаки по ID
- Фильтрация по разрешенным категориям

### L1EvaluationService
Сервис оценки результатов:
- Оценка списка результатов
- Оценка одиночного результата
- Формирование сводной статистики

## Infrastructure Layer (Инфраструктура)

### Репозитории
- `YamlL1AttackRepository`: загрузка атак из YAML файлов
- `YamlL1ConfigRepository`: управление конфигурацией в YAML формате

### Эмуляторы
- `BaseL1AttackEmulator`: базовая реализация эмулятора
- `BaseL1ResultEvaluator`: базовый оценщик результатов

## Принципы дизайна

### Domain-Driven Design
- **Entities** содержат только данные и простую логику
- **Value Objects** используются для immutable данных
- **Domain Services** выделены в отдельные классы
- **Repositories** абстрагируют доступ к данным
- **Factories** для создания сложных объектов

### Dependency Inversion
- High-level модули не зависят от low-level
- Все зависимости инжектируются через интерфейсы
- Абстракции не зависят от деталей реализации

### SOLID принципы
- **Single Responsibility**: каждый класс имеет одну ответственность
- **Open/Closed**: расширение через наследование и композицию
- **Liskov Substitution**: реализации заменяют интерфейсы
- **Interface Segregation**: узкие интерфейсы для конкретных нужд
- **Dependency Inversion**: зависимости от абстракций

## Поток данных

1. **Конфигурация** загружается из YAML
2. **Атаки** загружаются из репозитория
3. **Эмулятор** применяет санитизацию и инжектирует атаки
4. **Оценщик** анализирует результаты
5. **Сервисы** координируют работу компонентов

## Расширение

Архитектура позволяет легко добавлять:
- Новые категории атак через enum
- Дополнительные репозитории (БД, API)
- Специализированные эмуляторы для конкретных типов атак
- Кастомные оценщики результатов
- Интеграцию с внешними сервисами валидации
