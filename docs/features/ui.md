# Feature: PyQt UI

## Назначение
UI обеспечивает интерактивный контроль за прогоном тестов, выбор профилей и визуализацию результатов для исследовательских и демонстрационных сценариев, как описано в DOC1/DOC2 (режим исследователя vs. демонстрация). Включает управление подключениями к LLM для гибкой настройки интеграций.

## Архитектура
- `application/controller.py` – `UISuiteController`, фасад над `TestSuiteService`.
- `presentation/main_window.py` – главное окно PyQt:
  - выбор профиля,
  - выбор подключения к LLM (из `config/llm_connections.yaml`),
  - мультивыбор категорий и тестов,
  - запуск тестов и A/B прогонов,
  - таблица результатов с Pass/Fail, решением защиты, причиной.
  - кнопка «Управление подключениями» для открытия диалога настройки.
- `presentation/connection_management_dialog.py` – диалог управления подключениями:
  - `ConnectionManagementDialog` – основное окно с таблицей подключений и кнопками CRUD.
  - `ConnectionEditDialog` – форма редактирования подключения с валидацией.
- `presentation/main.py` – entrypoint `llm-security-ui`.
- Интеграция с `models` feature: `ModelConnectionService`, `ConnectionRepository`, domain entities (`ConnectionConfig`, `ConnectionInfo`).

## Поток работы
1. При запуске UI загружает список тестов и профилей (`controller.load_initial_data`).
2. Пользователь выбирает категории / конкретные тесты.
3. При желании переключает LLM-подключение (например, `dummy`, `openrouter_qwen_demo`).
4. При нажатии «Запустить профиль» запускается `run_suite`.
5. При нажатии «A/B прогон» вызывается `run_ab`, отображается `Δ Pass%`.
6. Таблица результатов обновляется в реальном времени, метрика Pass% выводится в статусной области.
7. Для управления подключениями: кнопка «Управление подключениями» открывает диалог. После изменений комбо-бокс подключений обновляется автоматически.

## Управление подключениями
- **Окно управления**: Модальное диалоговое окно (800x600) с таблицей подключений (столбцы: ID, Провайдер, Описание) и кнопками «Добавить», «Изменить», «Удалить».
- **Добавление/Редактирование**: Форма с полями для конфигурации подключения:
  - ID (обязательно, alphanum + _-),
  - Провайдер (dummy, openrouter),
  - Описание,
  - Model ID,
  - Base URL,
  - Timeout (сек),
  - Auth Type (env),
  - Auth Env Var,
  - Headers (key: value построчно).
- **Валидация**: Проверка формата ID, обязательности провайдера, корректности URL.
- **Интеграция**: Подключения сохраняются в `config/llm_connections.yaml`. Dummy встроенное, не удаляемое. Клиенты кэшируются в `ModelConnectionService` для производительности.
- **Workflow**: Пользователь добавляет/редактирует подключение, сохраняет, таблица обновляется. При ошибках – QMessageBox с деталями.

## Особенности UX
- Поддержка фильтрации (через чекбоксы категорий).
- Возможность выделять конкретные тесты для точечного прогона.
- Отображение решения защиты (`defense_decision`), что демонстрирует вклад слоёв (например, `block`, `rewrite`).
- В случае ошибок – диалог `QMessageBox` с сообщением (например, проблемы сети).
- Автоматическое обновление списка подключений после изменений.

## Требования
- Python 3.10+, PyQt6.
- Подключение к реальной модели не обязательно: UI работает с `DummyModelClient`.
