# Требования из DOC1 и DOC2

## Общая цель
Создать платформу для тестирования устойчивости LLM к prompt-инъекциям с фокусом на:
- автоматизированном прогоне заранее заданных сценариев атак;
- сборе метрик и сравнении результатов с/без защит;
- визуализации результатов через PyQt GUI;
- возможности демонстрации на конференциях и исследовательского анализа.

## Архитектурные принципы
- Clean Architecture с разделением на Domain / Application (UseCase) / Infrastructure / UI.
- Feature-first организация: каждая ключевая функциональность оформлена как самостоятельный модуль со слоями внутри.
- Defense-in-depth: модуль защиты реализован как конвейер из независимых слоёв (L1-L9).
- Расширяемость: возможность добавления новых тестов, моделей, защит, отчётов без модификаций базовой логики.

## Основные подсистемы

### Defense Pipeline
- Интерфейс `IDefenseLayer` с методами `before_send` и `after_recv`.
- `DefensePipeline` оркестрирует последовательный вызов слоёв, возвращает решения `Decision` (`allow`, `block`, `rewrite`, `escalate`).
- YAML-профили (`profiles.yaml`) управляют набором включённых слоёв и их параметрами.
- Политики (`policy.yaml`) описывают правила L4 Policy Engine.
- Слои защиты L1-L9 с указанными задачами (нормализация, классификация, firewall для контекста, политика, контроль инструментов, детектор суффиксов, output guard, memory guard, rate/scope).

### Тестирование и оценка
- `TestRunner` запускает тесты, поддерживает A/B прогоны (без защит / с профилем).
- Тесты определяются в YAML (`prompt_tests.yaml`) с категориями (direct prompts, role-play, obfuscation, payload split, adversarial suffix, prompt leakage, indirect/HTML и др.).
- `OutputEvaluator` классифицирует ответы на Pass/Fail на основе критериев из конфигов.
- Сбор метрик: процент проходов, распределение по категориям, вклад защит по слоям, ложные срабатывания, время ответа, длина ответа.
- Логирование артефактов (run_id, модель, профиль, layer_results, ответ, итог).

### Модели
- Поддержка удалённых API (OpenRouter и др.) и локальных моделей.
- Адаптеры `ModelClient` (унифицированный интерфейс) позволяют подменять реализацию.

### UI (PyQt)
- Главное окно с списком тестов и панелью «Защита» (профили, чекбоксы слоёв, индикаторы результатов).
- Поддержка режима A/B, фильтров по сработавшим слоям, отображение детальной информации по тесту.

### Отчёты
- Экспорт CSV/JSON и HTML с диаграммами, визуализацией вклада слоёв и A/B результатов.

## Дополнительные требования
- Настройки пользователя: сохранение выбранной модели, ключа API, оконного layout.
- Registry для тестовых результатов (audit trail).
- Возможность расширения тестовых сценариев новыми типами атак.
- Поддержка док-страниц с диаграммами (Mermaid).
- Демонстрационные профили защиты: `strict_demo`, `research`, `custom`.
- Метрики ложных срабатываний и указание слоя, заблокировавшего атаку.
- Поддержка отчётов об ошибках/эскалациях (Decision `ESCALATE`).
